# ADR 0008: Symbol generation in a `symbol` sub-package

## Status
Proposed. Draft by a contributor for discussion in #24; the maintainer
decides whether to accept, change or reject it.

## Date
2026-09-24

## Context
[ADR 0002](0002-parser-scope.md) puts barcode generation out of scope. That
decision was taken while the parser lived inside a larger application that
already had a generator. As a standalone module aimed at the GS1 LATAM
solution-provider certification, section 3.5 of the checklist asks the
software to print labels with GS1 symbologies, and integrators currently
combine a parser, an encoder and an unrelated renderer. FNC1 placement is
where those combinations break.

A dependency-free GS1 DataMatrix encoder was built on a fork to test the
cost: about 700 lines of non-test code, verified against zint module for
module and decoded by zxing-cpp.

## Decision

### Supersede the "no generation" clause of ADR 0002
Symbol generation is in scope. Print-quality verification (ISO/IEC 15415,
15416) and GS1 Digital Link stay out of scope.

### Sub-package `github.com/galenzo17/gs1-go/symbol`
| Option | Import cost for parser-only users | Discoverability |
|---|---|---|
| **Sub-package in this module** | **none: not imported, not linked** | **same repository, same release** |
| Separate module | none | second repository, versioning to keep in sync |
| Root package | image and png packages linked into every binary | high |

The sub-package keeps the root package, the CLI's parse path and the
WebAssembly build free of rendering code.

### Standard library only
Encoders are implemented from ISO/IEC 16022 and the GS1 General
Specifications. Output is an explicit `Matrix`, rendered to `image.Image`,
PNG or SVG by the standard library. ZPL is a text format and needs no
library either.

### Stateless functions, opt-in reuse
Package functions keep no state. Anything that trades memory for speed is
an explicit value owned by the caller, as `symbol.Encoder` does for module
layouts, following `png.Encoder`.

### Verification without test dependencies
Golden data is generated by an external reference encoder (zint) and
committed. Decoding with an independent reader (zxing-cpp) runs from a
script outside `go.mod`. Neither tool is needed for `go test`.

## Consequences
- ADR 0002 remains accepted for everything except the generation clause.
- New symbologies (GS1-128, GS1 QR, EAN/UPC, ITF-14) land as further files
  in `symbol`, each with golden data from a reference encoder.
- `gs1.Encode` (#16) becomes the single source of element strings for all
  symbologies once it lands.
- The CLI grows rendering commands; the WebAssembly bindings can expose
  them later (#21).
